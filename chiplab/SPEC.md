# Chip Lab: foundation

## 1. What it is
The place where an existing AI scientist designs, builds, tests and improves tiny chips for medical sensing devices. The AI scientist decides *what to try*. The lab *makes and measures* it, and returns honest numbers. Every capability is a tool the AI scientist can call.

**One chip = sensor input → one task → a decision**, computed on the chip with the model's weights wired into the logic. No memory fetches, no cloud, and the data stays on the device.

## 2. Languages and formats
| Layer | Format | Why |
|---|---|---|
| Task | JSON task spec | Readable by people and agents |
| Design | JSON design spec (model family, weights, bit widths, architecture) | What the AI scientist edits |
| Hardware description | **Verilog-2005**, generated by templates | What AI models write best, read by every open tool, correct by construction |
| Gate netlist | Yosys JSON netlist, plus gate-level Verilog | For simulation, proofs and visuals |
| Cell library | Liberty files (SkyWater 130, GF180, IHP) | Real area, timing and power |
| Waveforms | VCD | Timing views and power activity |
| Makeable outputs | FPGA bitstream (iCE40); GDS layout file (ASIC) | What a factory or board accepts |

Optional generators the AI scientist may use: alkaid (fixed multiplications as shifts and adds), TreeLUT (trees to Verilog), TorchLogix (logic-gate networks to Verilog).

## 3. What the AI scientist can change (the design space)
| Area | Settings |
|---|---|
| **Signal front-end** | Sample rate, analogue-to-digital bits, which features are computed off-chip vs on-chip (beat intervals, beat-to-beat change, raw samples, a heartbeat detector in gates) |
| **Input encoding** | Uniform bins, thresholds fitted to the data ("thermometer"), signed or unsigned, window length (number of beats or samples) |
| **Model family** | Integer neural network (binary, ternary, k-bit), logic-gate network, lookup-table network, decision tree or boosted trees, tiny 1D convolutional network, ensemble of small members |
| **Model size** | Hidden width, number of layers, number of ensemble members |
| **Numerics** | Weight bit width, activation bit width, shift and clip range, rounding, decision threshold |
| **Training** | Labels only or distillation from a full-precision "teacher", class weighting, number of rounds, random seed |
| **Hardware architecture** | One-pass (combinational) or clocked (sequential, smaller), pipeline depth, streaming input (one value per clock), output encoding |
| **Optimisation** | Gate set, how hard Yosys/ABC optimises, sharing repeated arithmetic |
| **Target** | Generic gates, iCE40 FPGA, Spartan-7 (for comparison), SkyWater 130, GF180, IHP SG13G2, flexible (Pragmatic) |
| **Budgets** | Maximum gates, lookup tables, area, power, latency; minimum sensitivity and specificity (the clinical floor) |

**Fixed by the lab, not editable:** the locked test set, patient-level splits, the baseline registry, and how each metric is computed.

## 4. How a design is made and measured
1. **Propose:** the AI scientist writes a design spec, or a batch of them.
2. **Train:** the whole batch trains at once on the GPU (population training).
3. **Compile:** templates produce the Verilog.
4. **Synthesise:** Yosys reports gate count by type and logic depth. It also reports the transistor estimate (`stat -tech cmos`), 6-input lookup-table count (`synth_xilinx`), and 4-input count (`synth_ice40`).
5. **Map to a real process:** SkyWater 130 / GF180 / IHP cells give area in µm² and gate-equivalents (area ÷ one NAND gate).
6. **Timing and power:** OpenSTA reports the slowest path (ns), power from switching driven by real sensor data, energy per decision, and standby leakage.
7. **Layout:** LibreLane or Tiny Tapeout's build gives the real area, design-rule checks, a GDS file and a layout image.

## 5. Verification ladder (a result only counts at the level it reached)
1. Bit-exact simulation: circuit = integer model = training model, on all test inputs.
2. **Formal proof:** Yosys `miter` + `sat` proves the circuit equals the model for every possible input.
3. Python testbench with real sensor recordings (cocotb with Icarus Verilog), plus a Verilator lint pass.
4. Gate-level simulation of the laid-out chip (Tiny Tapeout's gate-level test).
5. Running on real hardware: the iCE40 FPGA board.

## 6. How results are judged (the referee)
- **Clinical:** sensitivity, specificity and F1, per recording and per patient, with confidence intervals. Also tested on a second dataset the model never trained on (for example CinC 2017 → MIT-BIH AF database).
- **Hardware:** gates, gate-equivalents, lookup tables, transistors, area, logic depth, latency, energy per decision, power.
- **Robustness:** noise (the MIT-BIH Noise Stress Test database), input bit errors.
- **Baseline registry:** each published result is stored with its dataset, protocol and units. A "beat" only counts when they match. Current entries:
  - Andersson 2015, an AF chip working from beat intervals: 24,038 gate-equivalents, 334 nW, 94.9% sensitivity / 95.8% specificity.
  - Einhaus 2026, FPGA AF detectors: 536 lookup tables at 88.4% accuracy, and 2,844 at 95.6% F1.
  - A Cortex-M4 microcontroller model: 3,532 µJ and 143 ms per decision.
- **Rules:** never touch the locked test set during search, always label simulated vs measured numbers, and every claim must reproduce from a fresh seed.

## 7. What can be made (makeable outputs, prices checked 21 Nov 2026)
| Route | What the lab outputs | Cost and time |
|---|---|---|
| **FPGA (today)** | Bitstream for an iCE40UP5K | $36 UPduino board; days |
| **Tiny Tapeout, SkyWater 130** | Verilog repo; the GDS is built by their CI | €70 a tile (about 1,000 gates each), plus a €300 devkit; submissions close 30 Nov 2026, chips about June 2027 |
| Tiny Tapeout, GF180 / IHP | Same | Same pricing; GF180 closes 7 Dec 2026 |
| **wafer.space, GF180** | GDS with pin ring | $3,000 for 1,000 chips; GDS by 16 Dec, ships Q2 2027 |
| **Pragmatic FlexIC (flexible)** | GDS via Pragmatic's design kit (needs commercial tools) | €900/mm², 3×3 mm minimum ≈ €8,100 for 50; next deadline 16 Mar 2027 |

**Constraints the lab enforces:**
- Tiny Tapeout has 8 input, 8 output and 8 two-way pins, so inputs are streamed in (one value per clock, with a strobe pin).
- Tiny Tapeout designs are published openly.
- No route is medically certified.

## 8. Tools the AI scientist calls
`define_task` · `load_data` · `propose_designs` · `train_batch` · `compile_verilog` · `synthesize(target)` · `count_luts(family)` · `map_to_process(pdk)` · `simulate(bit_exact)` · `prove_equivalence` · `timing_power(pdk, activity)` · `layout(pdk)` · `evaluate_clinical(dataset)` · `compare_to_baseline` · `package(fpga | tinytapeout | gds)` · `estimate_cost` · `log_run`

Every call is logged with the spec, code hash, data-split hash, metrics, files and cost. That log is the leaderboard, the evidence of what was built today, the source of the visuals (candidate dots, stage changes, wire activity) and future fine-tuning data.

## 9. Where it stands today
- **Measured (feasibility test):**
  - 256 designs trained at once, 59× faster than one at a time;
  - a 2,330-gate, 52-deep ECG rhythm detector;
  - bit-exact on 3,880 of 3,880 unseen windows;
  - sensitivity 83% / specificity 88% per recording, against 97% / 95% for the full-precision model.
- **Next:**
  - distillation and data-fitted inputs to close the gap;
  - testing on the MIT-BIH AF database for the baseline comparison;
  - the formal proof, SkyWater 130 area and OpenSTA numbers;
  - the Tiny Tapeout wrapper and layout image.

## Appendix: implementation notes (added during the build, not part of the foundation text)

- **The lab is general.** The core (`ir/`, `emit/`, `verify/`, `hw/`, `referee/`, `data/`) holds no task-specific code. Sensors, datasets, front-ends, model families and simulators are plugins, and a test fails if task words appear in the core.
- **One integer IR (`chipir/1`)** is the contract between every model family and every hardware step. A family is accepted only if its trained model equals its IR bit for bit.
- **The sealed test set** is enforced by the API plus an audit log (`test_access.jsonl`, a counter shown on the leaderboard), not by cryptography. The agent has a shell and could read the cache, and the audit log makes that visible.
- **Scope:** the lab is the toolbox. It does not contain the AI scientist or its front end.
