TITLE: ['Chip design for medical devices']
BY: ['Notes written with Granola by Antonio']

Project Concept: AI-Assisted Chip Design for Medical Devices
Core idea: build an environment where AI scientists can design chips for medical sensing devices
Chips serve as the “core” of medical devices, taking sensor inputs and performing highly specific tasks
May run embedded AI/ML models, or simply combine sensor inputs
Optimized for efficiency and the specific application
Privacy is a key constraint: medical data cannot be sent to external servers (GDPR, hospital policy)
On-chip model hosting keeps data local and secure
Target Market and Scope
Domain: any medical device incorporating sensors
Considered too broad vs. too narrow; consensus: “sensors in medical devices” is appropriately scoped
Could be ultrasound, biosensors, diagnostics, etc.
Not a chip supplier per se: building the design environment that enables others to create chips
Potential market: US healthcare (NHS-scale funding noted as a signal)
The Design Environment
Agentic orchestration layer, not just a chatbot interface
User writes a prompt describing the chip/task
System spins up agents, runs experiments, proposes and tests chip designs iteratively
Multiple views available to the user:
Current design stage (ideation, testing, reporting)
Live agent commands and outputs
Cost tracking
Chip design sketch/image always visible
User can intervene, pause, or redirect at any point
Proposed workflow for chip design specifically:
Generate multiple chip design candidates
Simulate and validate each
Repeat iteratively
Output the best design
GPU Usage and Small Models
Available GPUs serve dual purpose:
Simulate the chip itself (hardware simulation)
Run small models locally, mirroring what would be embedded on the chip
Aligns with what some hackathon sponsors are looking for (small model focus)
Comparison to Existing Tools and Next Steps
Similar in spirit to Idea Labs AI (idea breakdown, go-to-market, team planning), but goes further
Idea Labs validates ideas; this environment runs real experiments and produces research-grade output
Pre-written code and existing repos are permitted for use
Transcript and code already recorded/shared among the group
